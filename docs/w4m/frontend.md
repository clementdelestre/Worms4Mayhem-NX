## 17. Frontend (`WXFE_*`): menus, screen state machine

(tags: [data] = read from tweak/exe data, [disasm] = read from code, [assumed] = inferred)

### Data sources
- Menus are pure data: `WXFE_MenuDescription` trees in the menu tweak databanks [data]. The databank name table at 0x91e15c (.data) lists, for PC: `MenuTwk`, `Persist`, `PersistPC`, `PersistNet`, `MenuTwkX`, `MenuTwkX2`, `MenuTwkXSteve`, `MenuTwkXInGame`, `MenuTwkXNet`, `MenuTwkXPCCommon`, `MenuTwkXPCEuro` (labels "Menu Tweak X", "Menu Tweak PC Only", "Menu Tweak Online", "Persistant"...) [data]. XBOX/PS2/PS3 files are not loaded by the PC exe: the PC loads its databanks by that name table, and they are not in it [data].
- Resource naming [data]: `WXFE.<Menu>` = full-screen menu, `WXFEP.<Name>` = popup, `WXNET.*` / `WXNETP.*` = network menus/popups, `<Menu>List` = `WXFE_ListBoxContents` the menu's list control binds to by `GameDataId`.

- Playback rate: the item start (0x755686) passes FrontEndService +0x134 as the clip speed; it is 1.1 at construction (0x7265b6) and then read from the data value `FE.AnimSpeed` (0x72a244 via XDataResourceManager), which `MENUTWKXINGAME` sets to 0.9 [disasm + data]. 0x6a03d0 hands the scheduler 1 / speed and the scheduler (XAnimScheduler +0x14, 0x7a9cf8) schedules the clip from now + delay over duration / (1 / speed), so every item clip lasts its length x 0.9 (in_tooltip 0.94 s, in_slidex 0.56 s, out_scaley 0.19 s); the delay itself is not scaled [disasm].
- Clips are evaluated on the exe's key curve (tools/w4m-models `curve()`, 0x7abb1c), not linearly: a zero out-tangent holds the key, weighted channels (flag 2) are Bezier with handles at key +- tangent / 3, unweighted ones Hermite on the tangent slopes [disasm].

### Screen state machine [disasm]
