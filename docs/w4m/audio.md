EFMV.Play sets the fade-out timer +0x24 = 500 ms (+0x20 = 0), EFMV.Terminated the fade-in +0x20 = 2000 ms (+0x24 = 0), both scale the same music volume. The music instance is +0x34 (Music/<theme>, Music/SuddenDeath via 0x605bf0). App.Resume (0x4e53c0, 0x4e550a) calls manager +0x2c (0x6f9880, same slot with 0 = setPaused(false)) for 0 and 3. So the sounds are paused in place and resume where they stopped, nothing is stopped or muted. So App.Pause pauses the SpotEffect and Speech categories and nothing else; the music keeps playing (x 0.5) and `AmbientEffect` (day/night ambience, FrontendDay) keeps playing. FEV categories (fev.py): every weapons/* event (Weapons: FuseLoop, ClockFast, ClockSlow, MineArmLoop, HolyGrenadeHeld, MissileLoop, FloodRainLoop / RainLoop, JetPack, Bomber, UFO, SentryGun...), cheer/cheer, global/* and frontendsfx/* (Global, Frontend) and the EFMVFoley events are `SpotEffect/*`; worm voices (Speechbanks) and EFMV dialogue are `Speech/*`; 11 events are `AmbientEffect`, 14 `music`. The pause also calls the kernel pause (0x4d7690 -> TaskManager vtable 0x884ddc slot 8 0x68ddc8 sets byte +0x3c = 1; Resume slot 9 0x68ddd8 sets 0). An event started in a paused category starts paused [disasm]: `EventI::start` 0x10014360 adds the event's channel group under its category's group (0x10015390, `ChannelGroup::addGroup` on category +0x70 -> +0x44; categories nest the same way, 0x1000e550) and calls `ChannelGroup::setPaused` with the event's own flag; fmodex `ChannelI::setPaused` 0x1006dead walks the channel's group (+0xac) and its parents (+0x24) and pauses the channel when any of them has its paused byte +0x61 set (`ChannelGroupI::setPaused` 0x1006b041 sets +0x61 and re-applies to child groups and channels). So every `frontendsfx/*` (`SpotEffect/Frontend`) and `global/*` (`SpotEffect/Global`) event started during the pause is silent until App.Resume [data: FEV categories; disasm].
- Pause menu sounds [disasm]: the frontend items play their Audio_Incoming / Outgoing / Highlighted / Activated through 0x755986: `PlaySound` 0x604a20 into the item's own XSoundInstance (+0x70), the previous one stopped first (0x7557c8, instance slot +0x14 = `Event::stop` 0x6fdfc0). The item destructor 0x7553c8 releases it, and the last release (0x6fdde0) stops the event while its state has `FMOD_EVENT_STATE_PLAYING` (0x6fe0c0, state & 8; a paused event keeps it). `KillPopUpNamed` kills the popup's tasks at once (TaskManager 0x68e18f, recursive, inside the message send), and every row that closes `WXFEP.Pause` sends it before `App.Resume`, so the popup's held item sounds are stopped before the categories resume: the pause menu's navigation, Audio_Incoming and options sounds are never heard. `WXMsg.PlaySample$<name>` (the menus' MenuGoingAway click3: WXFEP.Pause, the confirm popups, the briefing [data MENUTWKXINGAME]) plays through FrontEndService 0x726ef7 into the service's own instance +0x154 (`global/click3`, else `frontendsfx/<name>`; the previous one stopped first), which outlives the popup: the closing click3 is held and plays when App.Resume unpauses SpotEffect.
- Pause volume timing [disasm]: 0x605720 runs only from the AudioService update 0x605a70 (vtable 0x868ae0 slot 6, the sole caller) and only when its time argument moved (`0 < t - [0x9614dc]`; [0x9614dc] is updated every call, also without a music instance). The time is the TaskManager per-frame time, the clock rounded up to 20 ms (0x68d4d4), which does not advance while the kernel pause byte +0x3c is set (0x6f42b2). 0x605720: volume = Audio.Vol.Music, times the EFMV fade factor while +0x20 or +0x24 runs (+0x20 first, `elapsed` ms off each, int); then +0x28 -> x 0.5, flag cleared; else +0x29 -> flag cleared; else no timer: return (the last volume set is kept); the volume goes to the instance (vtbl +0x38). So x 0.5 holds until the next write (App.Resume's flag, or a fade timer step, which writes without the 0.5). Message sends are synchronous (0x6910e4 -> MessageRegistrationService HandleMessage 0x690abd -> 0x69111c calls every subscriber's HandleMessage in turn). App.Pause comes from InputService's update (0x691cd7 polls the device, whose raw messages InputTranslationService turns into `App.Pause`, sent at once offline, network.md), and InputService runs before AudioService in the per-frame list (both are Services, class flags 0xa = timed type 1, 0x68de04; a task returning 0 joins its type's per-frame list in the order of its first run, 0x68d6f1; InputService is added at app init 0x6f4999, AudioService later by MainServiceStartupLogicEntity 0x508ffd, a LogicEntity of type 2 (flags 0xb) that runs after the type-1 tasks of its time). So in the frame where the pause opens, the clock has already advanced (Task.Update adds dt before the tasks run): when that advance crossed a 20 ms boundary, AudioService consumes +0x28 in the same frame and the music is x 0.5 for the whole pause; otherwise +0x28 waits through the pause, and after App.Resume (+0x29 also set) the first moved update applies x 0.5 and the next one restores it (one 20 ms step at half). Ours: the same flags and 20 ms clock (`Audio::pause` / `update`, docs/audio.md "Pause").

### Speech (.lsd / LIP.txt) [data]
- Data/Audio/Speech/<voice>.lsd: text, blocks "<name>Speech/<voice>/<Category></name>" + one u32 line hash per variant + ";". 43 categories per voice = the 43 FEV events of group Speech/<voice> (list above). 33 .lsd files: 31 voices + voconfu, vowhoop (no fsb, no fev group).

- <game>/speech/<voice>/LIP.txt: "#<hash> <line text>.txt" header then "frame,VISEME,<none>" lip-sync rows; line text (truncated to 29 bytes) = FSB sample name. Exe: "Reading speech file " + ".txt", "Speech/<voice>/LIP".

## 12. Audio: WormsX.fev per-event data (extends §7)

### WormsX.fev (FEV1, ver 0x00400000, 1.3 MB): full layout, `tools/w4m-re/fev.py` [data: parses to EOF, all header counts match]
All integers are LE u32 unless noted. `str` = u32 length (NUL included) + bytes.
- Header: "FEV1", ver, 2 u32 (sizes?), u32 n=0x21, then n (id, value) pairs. These are object counts, verified: 1 banks=117, 2 categories=12, 3 groups=127, 5 params=1011, 6 envelopes=12, 7 envelope points=36, 8 sound instances=4127, 9 complex layers=1048, 10 simple events=1574, 11 complex events=1046, 13 waveforms=4058, 17 sounddefs=3995. Then `str` project "WormsX".
- Banks: count, then {loadmode, maxstreams, u64 hash, str name}.
- Categories (recursive, root "master"): {str name, f32 volume (linear gain), f32 pitch, u32, u32, u32 nchildren, children}. Tree: master/{music 0.501 (-6 dB), Speech/{EFMVDialogue, Speechbanks}, Custom, AmbientEffect, SpotEffect/{EFMVFoley, Weapons, Frontend, Global}}. Every category other than music is 1.0.
- Event groups: u32 nroot (=1, "Master"), group = {str name, u32 nprops, props {str name, u32 type (0 int, 1 float, 2 str), value}, u32 nsubgroups, u32 nevents, **events first, then subgroups**}. Group user props are only "LipSync" (EFMV groups).
- Event: u32 kind (0x10 simple, 0x08 complex), str name, 16-byte GUID, 0x84-byte property block (below), body, u32 ncat (=1), str category path (e.g. "SpotEffect/Weapons").
  - Property block [data; +00..+0C disasm, fmod_event.dll loader 0x10011b5f..0x10011bf9 (no conversion for FEV ver >= 0x210000)]: +00 f volume (linear, event +0x30), +04 f pitch (event +0x38; the channel pitch is 2^(4 x (pitch + random)), 1.0 = 4 octaves, 0x10013b80..0x10013bc2), +08 f pitch randomisation r (event +0x80; 0x10017230 draws uniform [-r, r), snapped to semitones / tones when event +0x60 bits 30 / 31 are set), +0C f volume randomisation r (event +0x84; volume x (1 - r + r x rand / 32767), 0x10013b0a). Only two events set any of the three: weapons/Debris (pitch rand 0.025: x 2^±0.1) and EFMV/DinerMight/Foley_FuseBurn (pitch 0.05: x 1.149), +10 priority (128; 64 on frontendsfx/click and every Speech/*/Sneeze), +14 max playbacks (1; 4 on ExplosionRegular/Boxed, BombWhistle, CowFall, FireLoop, SteamLoop, TeleportLoop...), +18 = 10000 always (steal priority?), +1C FMOD_MODE (0x08 = 2D, 0x10 = 3D, 0x100000 = log rolloff, 0x200000 = linear rolloff, 0x80000 = world-relative, 0x40000000 = ignore geometry), +20 f 3D min distance, +24 f 3D max distance, +28 flags (0x80000 on all Speech and 36 weapons; meaning unknown), +2C..+54 floats (cone 360/360/1.0 at +4C/+50/+54), +58 max-playbacks behaviour (1; 3 on ExplosionRegular, TeleportLoop, Thud), +5C/+7C f (1.0; 0.25 or 0.2 on the explosions, unknown), +6C fade-in ms, +70 fade-out ms.
  - Simple body: u32 1 + one sound instance.
  - Complex body: u32 nlayers, layers {u16 flags, i16 priority, i16 param index (-1 = none), u16 ninstances, u16 nenvelopes, instances, envelopes}, u32 nparams, params {str name, f velocity (units/s), f min, f max, u32 flags (3), u32, u32, u32 nsustain, f sustain[n]}, u32 (0).
  - Sound instance (58 bytes): u16 sounddef index, f start and f length on the layer's parameter axis (0..1), u32 start mode, **u32 loop mode (0 = loop, 1 = oneshot, 2 = loop and play to end)**, i32 loop count (-1), 4 u32 (0), f volume (1.0), 2 f (-1 on complex events, 0 on simple ones), 2 u32 (2, 2) [data: every "*Loop" event, the music tracks and the ambiences have mode 0, music/Victory has 1].
  - Envelope: i32 parent (-1, or the index of the envelope that shares the DSP), str DSP name ("" = built-in, "FMOD Highpass"), u32 DSP parameter index, u32 flags (0x0C = volume, 0x04 = DSP parameter, 0x14 = pitch?), u32, u32 npoints, points {f x (0..1 across the parameter range), f y (0..1), u32 shape}, 2 u32.
- Sounddef property sets: u32 count=35, each 70 bytes: u32 play mode, u32 spawn min ms, u32 spawn max ms, u32 max spawned, f volume (linear), ..., f at +52 (randomisation?), u16 trigger delay min/max ms at +64/+66  [play mode values: 3 on every 1-waveform def, 2 on most multi-waveform defs (random pick), 0/1/6 rare; enum not confirmed].
- Sounddefs: u32 count=3995, {str "/folder/name", u32 property-set index, u32 nwaveforms, waveforms {u32 type (always 0 = wave), u32 weight (100), str "file.wav", str bank, u32 sample index in the bank's FSB, u32 length ms}}.
- Reverbs: u32 count=1 ("Default"), str name + 132 bytes (I3DL2-like, not decoded). Then a "comp" chunk (u32 size=0x18, "comp", u32 0x10, "sett", 2 f 1.0) that runs to EOF.
- **Looping comes only from the FEV**: no sample in weapons/frontendsfx/global/ambient/mu*.fsb has an FSB loop flag (all mode 0x40200) [data]. The FEV instance loop mode alone decides loop vs oneshot.
- Envelope y -> gain [disasm + Ghidra/REA, fmod_event.dll]: the per-instance update FUN_1001acd0 (0x1001acd0..0x1001bb21) evaluates each envelope with FUN_1000f400 (point list at +0x30, count short at +0x34, point = x +8, y +0xc, shape +0x10, stride 0x14; segment shape read from the later point: 1 = cubic Bezier through y0,y0,y1,y1 via FUN_10012c40 (= smoothstep in x), 2 = linear, 4 = log curve, 8 = cubic S-curve, else 0; held at the last point). Flag 8 (0x0C volume envelopes) multiplies y linearly into the volume factor ([esp+0x54], 0x1001ae48); the final `Channel::setVolume` (0x1001b84c) is the plain product of the four factors (envelope volume, event/instance volumes, 1.0 for a Sound), with no dB conversion. Pitch envelopes (flag 0x10) go through base-2 pow of 8y-4 octaves (0x1001ae7c..0x1001ae94, 0x1003ac6c = 4.0). The first `setVolume` site FUN_10020770 (0x100207e8) is the same product without envelopes. Volume envelopes in WormsX.fev use shape 2 (24 points) and shape 1 (7 points, only EFMV/Tutorial3/Foley_WaterLap2); ours applies both through one helper, `envelope()` (audio.cpp), shared by `emitter()` (FloodRainLoop) and `efmvUpdate()` [ours]. MissileLoop's Time envelope is y 1 from 0 to 0.5029 then a step to 0, shape 2 (x equal on both points; 5.03 s at 0.1/s) [data]; main.cpp applies it as a hard cut at 5.029 s [ours].
- Loudness = event volume × sounddef-property volume × category gain (music = -6 dB) [disasm, fmod_event.dll: the sounddef and wave volumes go to `Channel::setVolume` (0x100207e8..0x10020864), the event volume and its randomisation to the event's `ChannelGroup::setVolume` (0x10013b42), and FMOD Ex multiplies a channel by its groups]. The exe's fire-and-forget call (0x604a80) passes an extra 1.0 volume.
- Speech: 1333 events, 3D linear 10..1000. 998 are complex, with a parameter "MultiSelect" 0..N and N instances that split the axis evenly (instance k covers [k/N, (k+1)/N]), one per spoken variant. At event creation the exe looks up the "MultiSelect" parameter handle (0x6f99a2, `getParameter`) and stores it (XSoundInstance +0x1c). Its start (vtable 0x89a344 slot +0x10, 0x6fde90) draws v = rand01 × max (getRange), nudged to max − 0.01 or 0.01 at the ends, and sets it (`EventParameter::setValue`): a uniform pick among the N variants [disasm]. 14 speech events name the parameter differently: "MultiStart" on StartTurn of vobuild/voprofe/vocave/voscot/voscous/vothief/vobarre, "MultSelect" on vocowbo/StartTurn, and "param00"/"param01" on a few Victory/WeaponFired/ShortOnTime/NoDamageA. They get no handle, so their value stays at the reset value: fmod_event 0x10024640 zeroes the normalised value, and `getValue` = min + (max − min) × that (0x1002446e); the FEV stores no initial value. ### Weights, play mode and taunt (sounddefs, EquipSfx, Input.TauntPressed)
- **Weights [data]**: `fev.py --json`, `sounddefs[i].waves[j].weight`, read for every event of `DEFS`. All 100 (OldWomanMutter 20 x5, not in `DEFS`) except **ScouserHeld 100/300/100**. Ours: `Def::w` in `audio.cpp`. Weights only count in the random modes (1, 2); ScouserHeld is mode 0, so they do not apply there [disasm, below].
- **Play mode: where it is read [disasm, fmod_event.dll]**: the first u32 of the 70-byte sounddef property set goes through setter 0x100384d0 into **bits 4..6 of the property word** (ctor 0x10038320: default 3); getter 0x10038490. The loader is 0x1002b510. The wave picker is **0x10038670** (n = wave count at +0x14, weights at [+0x28]+4+0x18*i, last wave +0x1c, state +0x18/+0x20/+0x24); its caller 0x10027fd4 sends mode 5 to 0x10027e10 (programmer-selected) and everything else to the picker.
- **Decoded values [disasm]**: 0 and 3 = sequential, index = (instance state + 1) % n, state at event-instance +0x40 (mode 3 resets it to -1 when the event starts at 0x1001cdcd, so it begins at wave 0; mode 0 copies the property word +0x1c at creation at 0x1001e1f4, 0 in every FEV def, so it begins at wave 1); 1 = weighted random (`rand() % sum(weights)`, cumulative walk); 2 = weighted random, and when it equals the previous pick (sounddef state +0x1c, -1 at start) it takes the next index; 4 = per-instance shuffle (list at instance +0x44, cursor +0x48); 5 = programmer selected; 6 = global shuffle (list +0x24, cursor +0x20, reshuffle 0x10038870 when spent, never starts with the last wave played); 7 = global sequential (+0x18, -1 at start). `rand` here is the CRT one.
- **Names [ours]**: the labels above (sequential, random, no repeat, shuffle, programmer) only describe the decoded code; the exe and the FEV carry numbers only. Data values: 3 on 3965 one-wave defs plus Foley_Splash, 2 on the 23 multi-wave defs (ExplosionRegular, SplashHeavy, ShotgunFire, Teleport, WingFlap, OldWomenFootsteps, Thud, CowFall, BubbleMachineLoop ...) and BombWhistle, 0 on OldWomanHeld / OldWomanMutter / ScouserHeld, 1 on ScouserJump, 6 on GrenadeImpact1 (our "bounce"); 4, 5, 7 are unused in the FEV.
- **Ours**: `Def::mode` (default 1) and `pick()` in `audio.cpp`: mode 2 rows (the ones above) keep a global last-pick, GrenadeBounce is a global shuffle, OldWomanHeld and ScouserHeld are mode 0, stepped per event instance from wave 1. The held sounds get one instance per `Accessory.Init`: WeaponAccessoryEntity 0x5950c0 stops and releases the previous +0xd0 instance and creates a new one (0x595192..0x59520d), and nothing else restarts it [disasm]. **Trigger delay** [disasm, fmod_event 0x10038400]: each sound waits min + rand() % (max − min) ms (min when equal) before it starts (a Channel delay, 0x1001a2f7): ScouserHeld 200..1200 ms, OldWomanHeld 200..1600, SheepHeld 1000..3000, OldWomenFootsteps 120, MissileLoop 1000. **Spawn** [disasm, fmod_event 0x10019c40]: a sound instance loads loop mode 0 / 1 / 2 as flags 0x02 / 0x04 / 0x10 (0x10029097); only flag 0x04 (FEV "oneshot") spawns: a countdown of min + rand() % (max − min) ms keeps running, and a new sound starts once it is out and fewer than max spawned (1) sounds exist, delayed ones included (0x1001a3ec). Spawn 0..1 (the held sounds, OldWomenFootsteps) thus repeats each sound right after the last, behind its trigger delay; BubbleMachineLoop spawns every 500 ms; spawn 0..0 plays once. Ours: `Def::delay` / `Def::spawn`, the pending queue in `Audio::update`, and `Audio::hold`, which runs one spawning instance while its condition holds.
- **Taunt key [data]**: `Input.TauntPressed` = DefInputMapping (LOCAL.XOM `InputEventMappingContainer` #1340, `FETXT.Control.Taunt`): keyboard `Key` 20 (DIK_T), no joypad entry among the 81 mappings.

### Our use (`client/src/audio.cpp`)
- `DEFS`: one row per `Audio::Sfx`, the W4M event its file comes from (`tools/w4m-import` `SFX`), its gain (event + sound definition + category dB), loop, 3D linear min..max in m (20 units/m) and max playbacks. 3D events fade linearly with the distance to the camera (`Audio::listen`) and pan; 2D events ignore it. Past max playbacks the oldest voice is cut. `SPEECH` / `SPEECH_SOFT` for the voices, `TRACKS` for the music.
- Looped while their state lasts (`Audio::loop`, called every frame): FuseLoop, MineArmLoop, HolyGrenadeHeld, cheer/cheer, WormPotLoop, ClockFast, ClockSlow, Bomber (`drawBomber`), SentryGunHeld (held Sentry Gun). SentryGun and RainLoop are loops in the FEV but our events only know their start, so they play one pass of the clip.
- **FrontendDay** [data, `fev.py -g frontendmusic`]: event frontendmusic/FrontendDay, loop, -3.0 dB, 2D, max playbacks 1, fade-in 0, fade-out 2000 ms, category AmbientEffect (1.0, not scaled by the music category); wave `FrontendDay` of bank frontendmusic (mp2 stereo 44.1 kHz, 196 s). Only one variant exists: no day/night versions [data]. FrontEndService init 0x72a34b starts it with femusic and its shutdown 0x7293dd stops both with the FEV fade-out (docs/w4m/frontend.md). `Audio.Vol.Music` scales only the music category (2). FrontEndService update 0x7290b4 [disasm] sets the category volumes every frame: 0 and 4 = `Audio.Vol.Sfx` (+0x168), 3 = `Audio.Vol.Speech` (+0x15c), **1 = `Audio.Vol.Ambient` (+0x164, `m_VolumeAmbientInst`)**, 2 = `Audio.Vol.Music` (+0x160) (mgr vtbl+0x44; the index switch 0x6f9740 maps 0 = SpotEffect, 1 = AmbientEffect [disasm 0x6f976a / 0x6f9784, jump table 0x6f97f4]); DEFSAVE defaults Ambient 1.0, Music 0.6, Sfx 1.0, Speech 1.0 [data]. So the FrontendDay ambience (category AmbientEffect) follows the Ambient option, and its instance volume (+0x150, set when it differs from the stored +0x13c) is `Audio.Vol.Sfx` [disasm 0x7290b4], i.e. FrontendDay gain = -3 dB x Sfx x Ambient. Every movie Open / Close sets femusic and FrontendDay to 0 / back (docs/w4m/acting.md "Music") [disasm 0x726b2f, 0x726b64, 0x7be8c8, 0x7beb9c].
- Fades: loops fade in and out by `Def::fade` (`Audio::loop`); a fire-and-forget start ramps its volume over the event fade-in (`Audio::play`: Teleport 350 ms, RainLoop 2000 ms); `frontendmusic/femusic` ("theme") fades out over 2000 ms when stopped or replaced (`Audio::music`).
