Removed as not W4M: the 1 s chase of every blast point (`Controls::impact`), hp-count tracks re-requested within 200 ms or for a worm already in clear view, the end of a death / count track without its RestTime, the flight to the new worm at turn start, the flight back to the worm after an event camera. The axis-cross test now takes the object's velocity only above W4M's 1e-5 u²/ms² (0.16 m/s), so a bobbing drowned worm falls back to the event direction.

W4M's lost test is the plain land segment camera → object (0x51abf0 → 0x466a20 → 0x4661a0: the whole segment, a hit anywhere before its end, no radius, flags 0); the object is the payload's own position (Radius 5 units keeps it off the land at contact); nothing skips it near the event point or close to impact, and one frame is enough (0x532589). Ours stops the segment 0.5 m short, so it is if anything more lenient.

PiP with the W4M serve rule (same matches, 366 turns): the CPU never moves while a camera is served, so the PiP never shows and the cuts are back to 3.43 per turn (shot 0.74, after the blast 0.10, retreat 0.92, hp count 0.65, turn start 1.01). The sim now starts the retreat at the launch, as W4M (w4m-map §14): a worm walking while its bazooka flies gets the shell's TrackCam in the PiP (`checkRetreatInFlight`). Walking is detected from the worm's position, since our walk sets no velocity.
